# translation-debt Specification

## Purpose

定义"翻译债"的登记与审查机制：凡原版有 Java 实现而本仓简化/未实现之处，都必须成为可
见、可追踪的债项，而不是被称作"自由设计"；并规定 review 时如何验证"逐行翻译"这一纪律
被真正执行。

## Requirements

### Requirement: 翻译债清单完整可核查

`openspec/progress.md` SHALL 登记全仓所有"原版有 Java 实现、本仓标为简化/占位/未实现"
之处，按大类分组，每条以 checkbox 呈现：未勾选 = 未完成，每条含：原版 `文件:行号`、
当前实现位置与做法、受影响观感。新增或修复简化点时 SHALL 同步更新该清单；完成债项
时 SHALL 勾选对应项。清单 SHALL NOT 承诺交付时间。本仓库 MUST NOT 在 `docs/` 下
维护第二份债清单（历史上为 `docs/translation-debt.md`，已迁出并删除）。

#### Scenario: 简化点未登记视为违规

- **WHEN** 代码中出现"简化/占位/暂不实现"的注释，而对应原版有 Java 实现
- **THEN** 判为违规；处置是登记进 `openspec/progress.md`（未勾选项），或按原版补齐实现

#### Scenario: 债项不得被称为自由设计

- **WHEN** 某处差异被归因为"自由设计"
- **THEN** 处置是核对原版是否存在对应 Java；存在则 MUST 改称翻译债

#### Scenario: 债项完成即勾选

- **WHEN** 某 untracked 债项在 change 中被补齐
- **THEN** `openspec/progress.md` 对应 checkbox 被勾选，条目保留作记录

### Requirement: 审查机制以判据清单为门禁

进入实现阶段的 change SHALL 在其 `design.md` 中列出本次用到的判据
`文件:行号`；缺失该清单者不得进入实现。审查 SHALL 抽样核对代码常量与表达式是否与所列
判据一致，重点核对**常量量纲**与**表达式顺序**这两类历史上反复出错的维度。

#### Scenario: 缺判据清单不得实现

- **WHEN** 一个 change 已有 tasks 准备进入实现，但其 design.md 未列出判据文件:行号
- **THEN** 不得开始实现，先补齐判据清单

#### Scenario: 审查盯住量纲与顺序

- **WHEN** 审查某段物理/编解码实现
- **THEN** 核对常量是否按原版口径代入（尤其属性值 vs 换算值）、表达式顺序是否与原版一致

### Requirement: 宿主机制与被托管物分离登记

当某项原版功能以"托管外部原版系 Java 产物"的方式提供（而非在 Dart 侧翻译原版实现）时，
登记 SHALL 分成两部分，缺一不可：

- **宿主机制**（承载方式：进程/嵌入式 JVM、日志管道、生命周期）MAY 标注为第三类自由设计
  "运行时宿主"，并写明平台 API 差异；
- **被托管物**（原版有 Java 实现、本仓未翻译而改为外部运行的部分）SHALL 照旧登记为翻译债，
  条目含原版 `文件:行号`、当前做法（"外部托管"）与判据位置。

MUST NOT 以"该功能已由外部产物提供"为由取消或省略债项。控制面/配置等**原版有实现且本仓
自行实现**的部分不属于被托管物，SHALL 照常逐行翻译，MUST NOT 借"运行时宿主"豁免。

#### Scenario: 托管型功能必须两头都登记

- **WHEN** 新增一个以托管外部 Java 产物方式提供的功能
- **THEN** 既在代码注释中标明宿主机制属于"运行时宿主"，也在 `openspec/progress.md` 登记
  被托管物的债项；只标其一视为登记不完整

#### Scenario: 审查据此校验

- **WHEN** 审查中看到某处标注为"运行时宿主"
- **THEN** 核对被托管物是否已有对应债项；未登记判为违规，处置是补登记或改为翻译原版

#### Scenario: 自行实现的控制面不得挂靠豁免

- **WHEN** 某段控制面/配置读写代码在原版存在对应 Java 实现，且本仓自行编写
- **THEN** 该段 MUST 逐行翻译并给出判据 `文件:行号`，MUST NOT 因同功能另有外部产物而
  援引"运行时宿主"豁免

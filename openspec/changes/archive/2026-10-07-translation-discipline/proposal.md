# Proposal

## Why

仓库总纲写着"Java→Dart 级忠实"，但它只是**描述性的一句话**，没有任何强制检查，于是实际
执行时反复偏离原版。2026-10-07 一天内连续三次：

|偏差 | 现象 | 根因 |
|---|---|---|
| 顺序错 |跳跃差 0.0031 格，够不上一格方块 | 把 `travelInAir` 的"先位移后扣重力"改写成"先扣重力再位移"（自认为等价）|
| 量纲错 | 飞行快 21 倍 | 判据 `getSpeed()` 返回**属性值 0.1**，却代入自己代码里的格/秒常量 4.317 |
| 擅自"合理化" | 飞行松手后失重悬浮 | 原版 `× 0.6` 被解读成 `max(injected, afterGravity)` —— 原版没有 `Math.max` |

三次都是"看起来对、实际偏几个数量级"。共同根因：**没有把"逐行翻译"当硬要求执行**，
也没有强制在写代码前先确认原版对应物。因此需要把它从"总纲描述"升级为**可判违规的契约**。

## What Changes

- 新增需求「Java→Dart 逐行翻译」：确立**写任何代码前必须先指名原版 Java 对应物**，
  并按原版的**表达式顺序、常量、分支条件**逐项对应；只允许三类自由设计（3D 渲染后端 /
  玩家输入来源 / 数据上行）。
- 明确「无法指出对应物 ⇒ 先停下查找；确实没有 ⇒ 必须在代码注释或提交信息里写明属于哪类
  自由设计或哪处 API 差异」，**"看起来原版也差不多"不算理由**。
- 明确「判据值必须能指向源码位置（文件:行号）；指不到即视为猜测」。
- 明确「测试断言原版离线递推的黄金值，不断言实现自身输出；测试失败先改实现」，
  以杜绝"改期望值迁就实现"。
- `AGENTS.md` 同步（它是摘要，规则正文在此）。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `project-structure`: 新增「Java→Dart 逐行翻译」需求——把总纲里的"忠实翻译"从描述性
  表述升级为带强制前置动作与可判违规情形的契约。

## Impact

- `openspec/specs/project-structure/spec.md`（新增一条需求）
- `AGENTS.md`（最高纪律段 + 踩坑表，摘要同步）
- 不改任何运行时代码；本 change 只立纪律。
